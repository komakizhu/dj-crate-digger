# 老炮DJ（dj-crate-digger）

中文名：老炮DJ；英文名、Skill 名与仓库名：`dj-crate-digger`。

面向 DJ、音乐制作人与电子音乐听众的 Agent Skills：把自然语言 Digging 需求转成经过联网搜索、逐曲验证、去重、排序和播放顺序设计的 Markdown 报告。

## 快速开始

在支持 Agent Skills 的客户端中直接说出 DJ 选歌需求即可。为了稳定触发，也可以使用：

```text
/dj-crate-digger
```

或：

```text
/迪歌
```

自然语言同样可以触发，例如：

```text
帮我为广州的地下俱乐部排一套 60 分钟 UK Bass set，参考 Skream 和 Nikita, the Wicked，不要口水歌。
```

完整流程固定为：发起需求 → 填写第一轮（含输出版本）→ 填写第二轮 → Agent 搜索并核验 → 返回歌单 → 可选反馈、导出或五度圈重排。

### 第一步：填写第一轮必要信息

Skill 会发送一个可复制的 Markdown 表单。可以复制示例，也可以自由填写；不填的字段由 Agent 根据已有信息判断。

例如（填写示例，仅供参考；可以直接复制后修改，也可以留空）：

```markdown
场景：地下俱乐部
目标国家 / 地区：中国大陆（广州）
核心声音方向：Skream、Nikita, the Wicked、现代 UK Bass、UK Dubstep
歌曲数量或 Set 时长：60 分钟
输出版本：简要版
其他限制：不要口水歌，不要过多人声
```

#### ！！！必看：选择输出版本

输出版本会决定返回内容、详细程度和速度。请在第一轮的“输出版本”一栏选择一个：

| 版本 | 适合什么时候用 | 输出内容 |
|---|---|---|
| 极速版 | 想快速拿歌 | 约 15 首，只有歌名、歌手、链接 |
| 简要版 | 想要一份完整歌单 | 一份歌单，附调性、理由和接歌建议 |
| 丰富版 | 想比较不同方向 | 四个不同方向的歌单，以及最后的综合版（共五份） |

第一轮决定的是“这套歌单要解决什么问题”：在哪里播放、面向哪个地区、核心声音是什么、做多长、选择哪种输出版本以及有哪些硬限制。

### 第二步：填写第二轮细节

Agent 收到第一轮后会发送第二个表单，用来确定更具体的音乐方向和编排细节。

例如（填写示例，仅供参考；可以直接复制后修改，也可以留空）：

```markdown
具体风格：UK Bass / UK Dubstep
速度 / BPM：130–140
熟悉度与发现感：平衡
时代与经典：少量经典锚点
情绪：深沉 / 阴冷
SET 能量级或能量走势：平稳抬升
平台与链接要求：网易云
其他：避免同一艺人连续出现
```

第二轮答复后，Skill 会直接开始搜索，不再增加第三轮普通需求问卷。

### 第三步：等待推荐报告

## 平台与链接怎么填

在第二轮填写平台名称即可，例如“网易云”表示只使用网易云；填写多个平台时用 `/` 分隔，越靠前优先级越高。留空则使用跨平台模式。平台选择只影响搜索范围和最终链接，不改变选歌方向。

## 推荐完成后可以做什么

推荐完成后，你可以直接用自然语言反馈喜欢、不喜欢、会不会使用某首歌，系统会先调整当前会话。简要版和丰富版还可以回复“需要”或“按五度圈排”，让系统根据已知调性重新排列 set；也可以直接回复 `输出文字版歌单` 或 `导出到w4dj`。

## 输出文字版歌单或 W4DJ

推荐完成后直接回复：

```text
输出文字版歌单
```

或：

```text
导出到w4dj
```

这些输出都使用最终交付结果：极速版使用最终极速表，简要版使用综合表，丰富版使用动态综合版；如果已经完成五度圈重排，则使用重排后的顺序。

### 文字版歌单

`输出文字版歌单`的功能：输出可复制文本，可以手动导入网易云，但无法帮您一键把歌曲导入 RKB。

### TXT

旧指令 `导出txt` 仍作为兼容入口。TXT 是 UTF-8 纯文本，每首一行：

```text
Artist — Official Track Title — https://direct-track-url
```

同一录音只写一次；没有符合平台策略的已核验直链时跳过该曲，并说明原因。

### W4DJ

`.w4dj` 是 UTF-8 JSON v2 交接文件，不是音频文件。它只保存协议字段、歌单名、歌单顺序、完整官方曲名和艺人；如果有网易云身份，则以 JSON 字符串保存可选的 `netease_track_id`。官方歌名中的 Remix、Edit、Live、Dub、Extended Mix 等限定直接保留在 `title` 中，不另设 `version` 字段。

W4DJ 文件固定使用 `format_version: 2`，不包含 BPM、调性、专辑、URL、平台状态、内部 `dedupe_key`、本地文件名或路径。旧 v1 文件直接拒绝，必须重新导出 v2，不做迁移；完整结构见 [references/w4dj.schema.json](references/w4dj.schema.json)。

如果当前 Agent 没有文件写入能力，它只能返回等价的 TXT 内容或 W4DJ JSON manifest，并明确说明没有实际创建文件。

## 常见问题

### 为什么一定要两轮？

第一轮确定演出任务、输出模式和硬限制，第二轮确定具体声音与平台。第二轮结束后直接搜索，避免一边找歌一边反复修改目标。

### 可以不填某些字段吗？

可以。留空表示允许 Agent 根据已经提供的线索判断。明确填写的地区、平台、禁用项和完整官方曲名限定属于硬约束，优先级高于自动推断。

### 为什么实际曲目可能少于要求？

当目标平台缺曲、完整官方歌名无法核验或候选重复时，Skill 会减少数量，而不是使用其他平台、错误歌名限定或虚构链接凑数。

### 能直接写入 Spotify、Apple Music 等平台歌单吗？

只有当前客户端具备官方授权连接器、用户明确确认目标平台和曲目摘要后才能执行。否则只输出经过验证的 Markdown、TXT 或 W4DJ，不会声称已经创建平台歌单。

### 这个 Skill 能识别正在播放的歌曲吗？

不能。它负责发现、筛选、排序和编排 DJ 歌单，不是听歌识曲工具。

## Agent Skills 兼容性与来源

本仓库以标准 `SKILL.md` 作为通用入口，`references/` 是按需读取的补充资源；支持 Agent Skills 标准的客户端可以按自身的技能目录发现并加载它。Claude Code、VS Code Agent 等支持该标准的客户端可以复用核心内容，但具体发现目录、权限确认和工具名称由客户端决定。

本版本基于 Codex 版 `dj-crate-digger` Skill 修改为 Agent Skills 通用格式，中文名为「老炮DJ」。`agents/openai.yaml` 仅是 Codex 的可选 UI 与调用适配层，不包含独有的推荐算法；其他 Agent 可以忽略该目录，直接使用 `SKILL.md` 与 `references/`。不支持 Agent Skills 的客户端需要手动加载 `SKILL.md`，并将搜索、页面核验、文件写入和后台续跑映射到自身能力。
