# DJ Crate Digger Skill

面向 DJ、音乐制作人与电子音乐听众的 Codex Skill：把自然语言 Digging 需求转成经过联网搜索、逐曲验证、去重、排序和播放顺序设计的 Markdown 报告。

## 本版重点

- 中文 DJ 口语与场景语义归一化，区分参考艺人与专题目标。
- SoundCloud → Apple Music → Spotify 默认链接展示顺序；跨平台发现采用均衡轮询，用户首选、允许和禁用平台可覆盖默认值。
- 候选池按目标数自适应扩展；每首最终曲目逐条打开直接页面核验，播放链接与核验来源分开记录。
- 触发后严格用两轮收集需求：第一轮确认场景、核心声音方向、歌曲数量或 Set 时长和其他限制；第二轮完成风格、BPM、流行度、输出版本、情绪、能量、平台与链接要求和其他限制。
- 两轮提问在所有环境中固定使用两段可复制的 fenced Markdown 代码块；AI判断和空白语义只在第一轮说明一次；简要版默认输出，用户填写丰富版时才展开四种视角。
- 丰富版共享同一验证候选池；简要版采用 Warm Up → Groove → Peak → Closing，并跨段去重。
- 网易云音乐和 Beatport 纳入平台与链接要求的可选范围；平台不可用时透明标记，不伪造可用性。
- 动态内容权重只在风格、场景、流行度之间分配；平台顺序不混入内容排序。
- 目标平台缺曲时按 preferred / exclusive 分层降级，不自动替代、不越权导出。
- 推荐报告结束后才询问本地 TXT / M3U8 导出；确认后按最终综合顺序生成 UTF-8 文件，并透明列出无链接而跳过的曲目。
- 触发词覆盖 /迪歌、挖歌、找歌、排set、排歌单、setlist、crate digging 等挖歌与 DJ 编排表达；泛 playlist/歌单请求需要 DJ 或音乐策划语境。

## 目录

- `SKILL.md`：主工作流与安全边界
- `references/`：搜索验证、动态排序、报告模板和平台导出规则
- `evals/evals.json`：25 个行为评测，覆盖两轮需求收集、固定 Markdown 提问格式、必要信息与需求细化模板、平台发现与链接优先级、逐曲核验、自适应预算、综合/四版本、版本去重、降级和 TXT/M3U8 本地导出
- `evals/trigger-evals.json`：触发与反触发样例
